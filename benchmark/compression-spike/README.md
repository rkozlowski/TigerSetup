# Compression-architecture spike

Evidence for the post-ZIP payload architecture decision: **Zstandard or
LZMA2** for a solid-compressed region, at what settings, in what file order,
in one stream or in bounded blocks, and whether TigerSetup 0.7.1's
"already compressed" classification still holds for those codecs. The
durable result is [`report.md`](report.md), generated by
`scripts/New-Report.ps1` from `results/`. Nothing here is a product change:
`crates/` does not see these codecs, the payload format is untouched, and
the spike tool is disposable benchmark machinery.

## Layout

```text
benchmark/compression-spike/
  README.md                this file
  report.md                the generated report (the deliverable)
  tool/                    cspike, the spike tool: a Cargo workspace of its own
    src/classify.rs        0.7.1's signature/probe rules reproduced; the file families
    src/codec.rs           store / DEFLATE (flate2+zlib-rs) / zstd / raw LZMA2 behind one streaming interface
    src/inventory.rs       per-file classification, DEFLATE-9 baseline, stored files compressed alone
    src/layout.rs          partitions (current / signature / all) and layouts (path, families, the static type family, basename locality)
    src/worker.rs          the measured work, one child process per measurement
    src/run.rs             plan runner: wall time, peak memory, SHA-256, resumable results
  scripts/
    Acquire-Corpus.ps1     downloads the pinned OSS artifacts, verifies published hashes
    New-CorpusPayloads.ps1 materializes every payload tree, recording each normalization
    Invoke-Inventory.ps1   cspike inventory for every payload -> results/inventory/<App>.json
    New-Plan.ps1           builds a plan (apps x partitions x layouts x settings x blocks)
    New-Report.ps1         generates report.md from results/
  corpus/       (gitignored) downloads/, <App>/_extracted, <App>/payload
  work/         (gitignored) file lists, plans, compressed outputs in flight, logs
  results/                 the committed machine-readable evidence
    corpus.json            the pinned corpus: sources, versions, hashes, licences, exclusions
    oss-apps-research.json the acquisition research record for the seven extra OSS apps
    corpus-downloads.json  what was downloaded, observed hashes
    corpus-payloads.json   every payload tree, its file count, bytes and normalizations
    inventory/<App>.json   per-file classification, family, DEFLATE-9 size, stored-alone sizes
    stage1.json            codec x level, one stream, path order, current partition
    stage1b-window.json    the window/dictionary follow-up (zstd-19 at 64/256 MiB, LZMA2-9 at 128/256 MiB)
    stage1c-bcj.json       x86 BCJ filter ahead of LZMA2-9 (64 and 128 MiB)
    stage2-per-file.json   every file compressed independently
    stage2-partitions.json signature-only and admit-everything partitions
    stage2-layouts.json    the five layouts against path order
    stage2b-order.json     (2026-09-20) the type-family and basename layouts against ext-path, everything admitted
    stage3.json            bounded blocks (32/64/128 MiB) in path and extension order
    determinism.json, determinism-blocks.json   repeated compressions, hashes compared
    benchmark-installers-layout.json            the real 0.7.1 benchmark installers' block layout
    versions.json          the codec libraries and compiler the tool was built with
    narrative.md           the outliers and recommendation sections the report embeds
```

## Reproducing

```powershell
cargo build --release                                       # tiger-setup (decomposes TigerSetup installers)
pwsh -File benchmark\scripts\Acquire-Downloads.ps1          # the four canonical payloads, if not present
pwsh -File benchmark\scripts\New-CanonicalPayload.ps1
cd benchmark\compression-spike
cargo build --release --manifest-path tool\Cargo.toml       # cspike
pwsh -File scripts\Acquire-Corpus.ps1                       # 7 pinned OSS artifacts (6 usable; see corpus.json for GIMP)
pwsh -File scripts\New-CorpusPayloads.ps1                   # 15 payload trees; Tiger apps from local release payloads
pwsh -File scripts\Invoke-Inventory.ps1
$run = 'tool\target\x86_64-pc-windows-msvc\release\cspike.exe'
$plan = 'scripts\New-Plan.ps1'
pwsh -File $plan -Name stage1 -Settings store,deflate-9,zstd-3,zstd-12,zstd-19,zstd-19-w27,zstd-22-w27,lzma2-3,lzma2-6,lzma2-9,lzma2-9e -Parallelism 2
& $run run --plan work\plans\stage1.json --results results\stage1.json
pwsh -File $plan -Name stage1b-window -Settings zstd-19-w26,zstd-19-w28,lzma2-9-w27,lzma2-9-w28 -Parallelism 3
& $run run --plan work\plans\stage1b-window.json --results results\stage1b-window.json
pwsh -File $plan -Name stage1c-bcj -Settings lzma2-9-bcj,lzma2-9-w27-bcj -Parallelism 3
& $run run --plan work\plans\stage1c-bcj.json --results results\stage1c-bcj.json
pwsh -File $plan -Name stage2-per-file -Settings zstd-19,lzma2-9 -PerFile -Parallelism 6 -DecompressReps 0
& $run run --plan work\plans\stage2-per-file.json --results results\stage2-per-file.json
pwsh -File $plan -Name stage2-partitions -Partitions signature,all -Settings zstd-19-w27,lzma2-9 -Parallelism 6 -DecompressReps 1
& $run run --plan work\plans\stage2-partitions.json --results results\stage2-partitions.json
pwsh -File $plan -Name stage2-layouts -Layouts ext-path,text-first,binary-first,largest-first,text-first-ext -Settings zstd-19,zstd-19-w27,lzma2-9 -Parallelism 6 -DecompressReps 1
& $run run --plan work\plans\stage2-layouts.json --results results\stage2-layouts.json
pwsh -File $plan -Name stage2b-order -Partitions all -Layouts path,ext-path,ext-basename-path,type-path,type-basename-ext-path,type-ext-basename-path -Settings zstd-19-w27 -Parallelism 6 -DecompressReps 0
& $run run --plan work\plans\stage2b-order.json --results results\stage2b-order.json
pwsh -File $plan -Name stage3 -Apps VSCode,Inkscape,ShareX,GitForWindows,Wireshark,qBittorrent,VLC,WinMerge,Tiger3dForge,TigerMarkView -Layouts path,ext-path -Settings zstd-19-w27,lzma2-9 -BlockBytes 33554432,67108864,134217728 -Parallelism 6 -DecompressReps 1
& $run run --plan work\plans\stage3.json --results results\stage3.json
pwsh -File $plan -Name determinism -Apps GitForWindows,VLC,WinMerge,TigerMarkView -Settings deflate-9,zstd-3,zstd-19-w27,lzma2-6,lzma2-9 -CompressReps 2 -DecompressReps 1 -Parallelism 4
& $run run --plan work\plans\determinism.json --results results\determinism.json
pwsh -File $plan -Name determinism-blocks -Apps GitForWindows,VLC,WinMerge -Settings zstd-19-w27,lzma2-9 -BlockBytes 33554432 -CompressReps 2 -DecompressReps 1 -Parallelism 4
& $run run --plan work\plans\determinism-blocks.json --results results\determinism-blocks.json
pwsh -File scripts\New-Report.ps1
```

The runner appends each finished job to its results file and skips jobs
already there, so an interrupted run resumes. Compressed outputs are deleted
after their decompression runs; only their SHA-256 is kept. Stage 1 and the
window study ran two and three jobs at a time (their times and memory are
the report's timing evidence); the BCJ, Stage 2 and Stage 3 plans ran up to
six at a time and alongside each other, so their sizes are exact and their
times indicative only. `results/benchmark-installers-layout.json` was
produced with `tiger-setup inspect --json` on the four benchmark installers.

## What is measured, and how

- **One child process per measurement.** `cspike run` spawns
  `cspike worker compress|decompress|per-file` for every job; the worker
  times only its own codec loop (files streamed from disk through the
  encoder to a file; the compressed file streamed through the decoder into
  a CRC-32), and the runner reads the child's peak working set and peak
  commit charge from the process object after it exits. Memory numbers are
  therefore the whole child process — codec state plus ~5 MiB of runtime and
  1 MiB buffers — measured, not estimated from a formula.
- **Single-threaded codecs**, no checksums, no container beyond the codec's
  own frame: a zstd frame with pledged size, a raw LZMA2 stream, a raw
  DEFLATE stream. What the results name is what ran; every job records the
  codec's effective parameters as the library reports them.
- **Decompression is a streaming decode** repeated three times; the median
  is reported and every run's wall time is kept.
- **Determinism** is checked by compressing twice in separate processes and
  comparing the SHA-256 of the outputs.
- **Baseline.** `cspike inventory` reproduces 0.7.1's per-entry decision
  (`crates/tigersetup-format/src/payload.rs`: format signatures, extension
  list, the sampled probe with its constants) and its DEFLATE-9 encoder and
  backend, per file. The sum agrees with the payload block of the real
  0.7.1 installers to within the ZIP headers (WinMerge: 24,797,947 against
  a 24,861,078-byte payload block holding 473 entries).
